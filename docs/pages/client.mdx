# TypeScript Client

The `ronin` npm package lets you query your RONIN database from any TypeScript environment — server scripts, background jobs, or frameworks other than Blade. Inside a Blade app you use the `use` and `useMutation` hooks instead, but the `ronin` client is useful anywhere those hooks aren't available.

## Basic Usage

The client reads your App Token from the `RONIN_TOKEN` environment variable automatically, so no code-level setup is required:

```ts
import { get } from 'ronin';

const posts = await get.posts();
```

If `process.env.RONIN_TOKEN` is not in scope — for example in some edge runtimes — pass the token explicitly:

```ts
import roninFactory from 'ronin';

const ronin = roninFactory({
  token: 'YOUR_APP_TOKEN',
});

const posts = await ronin.get.posts();
```

## Batching (Transactions)

When you run multiple write queries at once, wrap them in `batch` to guarantee atomic execution. If one query fails, all others are rolled back:

```ts
import { batch, set, add } from 'ronin';

const [account, session] = await batch(() => [
  set.account({
    with: { id: '1234' },
    to: { emailVerified: true },
  }),
  add.session.with({
    account: { id: '1234' },
  }),
]);
```

You can also use `batch` for read queries to send a single network request instead of one per query:

```ts
import { batch, get } from 'ronin';

const [account, session] = await batch(() => [
  get.account.with.id('1234'),
  get.session.with.account.id('1234'),
]);
```

## Caching

If your framework caches outgoing `fetch` requests, pass custom fetch options when constructing the client:

```ts
import roninFactory from 'ronin';

const ronin = roninFactory({
  fetch: { next: { revalidate: 3600 } },
});
```

For `add`, `set`, and `remove` queries, the client defaults to `cache: 'no-store'` to prevent stale writes.
