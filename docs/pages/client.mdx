# TypeScript Client

The `ronin` package on npm gives you direct access to your RONIN database from any TypeScript environment — a Node.js script, a Next.js route handler, a serverless function, or anywhere else with network access. You don't need a running Blade app to use it.

## Basic usage

By default, the client reads your App Token from the `RONIN_TOKEN` environment variable and requires no further setup:

```ts
import { get } from 'ronin';

const posts = await get.posts();
```

If `process.env.RONIN_TOKEN` is not available in your environment, pass the token explicitly:

```ts
import roninFactory from 'ronin';

const ronin = roninFactory({
  token: 'YOUR_APP_TOKEN',
});

const posts = await ronin.get.posts();
```

## Batching queries (transactions)

When running multiple write queries at the same time, batch them together to ensure atomicity. If one query fails, all others in the batch are rolled back:

```ts
import { batch, add, set } from 'ronin';

const [account, session] = await batch(() => [
  set.account({
    with: { id: '1234' },
    to: { emailVerified: true },
  }),
  add.session.with({
    account: { id: '1234' },
  }),
]);
```

You can also batch read queries to reduce the number of network round trips:

```ts
const [account, session] = await batch(() => [
  get.account.with.id('1234'),
  get.session.with.account.id('1234'),
]);
```

## Caching

If your framework caches outgoing `fetch` requests (Next.js does this), you can pass custom fetch options to control caching behavior:

```ts
const ronin = roninFactory({
  fetch: { next: { revalidate: 3600 } },
});
```

For `add`, `set`, and `remove` queries, the client sets `cache: 'no-store'` by default so mutations are never served from a stale cache.
