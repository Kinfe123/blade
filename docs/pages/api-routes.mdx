# API Routes

In Blade, all interactions with the server flow through two hooks: `use` for reads and `useMutation` for writes. This means you almost never need to write a REST API for your own frontend — Blade handles the transport for you.

## How data flows

Reads happen on the server through the `use` hook in layouts and pages. Writes happen from client components through `useMutation`. To run arbitrary server-side logic alongside a read or write, you use Triggers (most commonly a `during` trigger).

Blade combines all `use` queries on a page into a single database transaction. When a `useMutation` call runs, Blade adds the necessary re-fetch queries to the same transaction, so the UI update and the data write are atomic.

## When to expose a REST API

You should expose a REST API only when an external client — a mobile app, a third-party integration, or another service — needs to access your data.

For those cases, Blade auto-generates a REST API at `/api` for any Trigger file that opts in:

```ts
// triggers/post.ts
export const exposed = true;

export const duringAdd = (query, multiple, options) => {
  // validate and run the query
  return query;
};
```

Adding `export const exposed = true` makes Blade expose the Trigger's schema at `/api/post`. You should never call these APIs from within your own Blade application — doing so introduces a network round trip and loses the batching benefit.

## Custom routes with Hono

In rare cases where you need a route with a specific request signature (for example, a Stripe webhook), add a `router.ts` file at the project root:

```ts
import { Hono } from 'hono';

const app = new Hono()
  .post('/webhooks/stripe', async (c) => {
    const payload = await c.req.json();
    // handle the webhook
    return c.json({ received: true });
  });

export default app;
```

Blade mounts this Hono app on the same domain as your pages. Routes in this file cannot call Blade's `use` or `useMutation` hooks — they are a separate layer.

> **Note:** Custom routes and Blade pages are intentionally isolated. The Hono app handles its own routes; Blade pages handle everything else. Do not try to bridge them by importing page hooks into the router.

## Triggers

Triggers are TypeScript functions that run when a particular query type executes. They live in a `triggers/` directory at the project root, with one file per model slug:

```ts
// triggers/post.ts
import type { DuringAddTrigger } from 'blade/types';

export const add: DuringAddTrigger = (query, multiple, options) => {
  // validate the incoming `add.post` query
  // or run additional queries inside the same transaction
  return query;
};
```

Triggers can be typed as `before`, `during`, `after`, `resolving`, or `following`, each running at a different point in the query lifecycle. The `during` trigger is the most common — it intercepts the query and can modify it or replace it entirely.
