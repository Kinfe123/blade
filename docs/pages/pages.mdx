# Pages

Blade pages live in your project's `pages/` directory. The file `pages/index.tsx` is the root of your application. Dynamic routes use bracket notation — for example, `pages/posts/[id].tsx` matches any URL like `/posts/some-slug`.

## Automatic Revalidation

Blade intelligently keeps your data up to date so you don't need a separate state management library. Read query output is refreshed:

- In the same database transaction as any mutation that affects those records.
- Every 5 seconds, even when the window is not in focus.
- When the device goes back online after being offline.
- When the browser window regains focus.

The application itself is also revalidated. When you deploy a new version, Blade detects the drift between the running client and the latest server assets, then seamlessly updates the client with the new code. React itself is also versioned — if you upgrade React, Blade unmounts the old version and mounts the new one without a full page reload.

## MDX

Blade supports MDX (Markdown + JSX) with zero configuration. Create any file with the `.mdx` extension inside `pages/` and it will be treated as a page. You can write standard Markdown and embed React components side-by-side:

```mdx
# Hello

This is regular Markdown.

<MyComponent />
```

MDX pages have full TypeScript support for any components you embed.

## Layouts

You can create a `layout.tsx` file in any directory inside `pages/`. Blade wraps all pages in that directory with the layout automatically, letting you share navigation, headers, and other UI without repeating yourself.
